# Typed job suite: synthetic browser qualification

Extension 0.3.0, job protocol 2. This extends the paired desktop worker without
changing its Chrome permissions. All requests in this verification are intercepted
by a stateful synthetic Google fixture. No real Google account is used or changed.
This is not live mutation qualification.

The actual extension pairs with a disposable PhotoFlow HTTPS/WSS app through its
web UI. The workbench queues a finite read/write suite and inspects each result.
It then simulates a write whose response is lost after the server applies it,
confirms an unknown outcome, and reconciles with reads without another write.

Observed result: 28 completed jobs covering all 22 registered operation types;
122 synthetic Google requests; account-bound pairing, WSS delivery, progress,
result persistence, sanitized diagnostics and read-only reconciliation pass.
The fixture finishes the suite with favorite/archive/trash/membership/manual
location states restored; timestamp changes and a newly created test album persist.

The real browser test exposed Chrome argument conversion omitting null object
properties in injected requests. The injection adapter now transports a JSON
string and the self-contained page handler parses it before validating explicit
null target bindings. Missing bindings are still rejected. A regression test
covers album creation's null targets and request-array nulls. Checksummed browser
journal data and intent comparisons use canonical object key ordering so storage
serialization does not cause false corruption or replay decisions.

The native test suites also cover invalid scopes, account switches, unsupported
inputs/results, album ID namespaces, persisted locks, corrupt journals, unknown
location state, lost acknowledgements and idempotent completion receipts.
No production mutation qualification gates were removed. The production test
account setting remains unset. Live read and mutation qualification must be
reported separately; see ADR 0005 for the isolated-account procedure.

Validation: 116 Google package tests, 73 web tests and 24 UI tests pass. Both
Chromium scenarios pass, and the packed standalone library imports successfully.
Deployment checks return public health 200, unauthenticated worker status 401,
and a byte-identical extension ZIP. WSS upgrades through Cloudflare/nginx and
rejects an invalid protocol-2 credential with close code 1008. The production
systemd environment has no configured test account. No live Google mutation
qualification was performed.

## Owner-authorized selected-target policy (0.3.1)

ADR 0006 records the owner's explicit authorization to use the backed-up personal
account for finite pilots. A separate account is optional. Automated tests remain
synthetic: the selected-policy browser fixture uses a normal personal-style
filename, a 20 MiB image and a private album without the test prefix. Both fixture
and selected policies complete 28 jobs / 22 operation types / 122 intercepted
requests, including lost-acknowledgement reconciliation without replay.

120 package tests, 76 web tests and 24 UI tests pass. Regression cases cover
unconfigured/different accounts, explicit confirmation, unknown policies, queued
policy changes, target/expiry binding, shared-album rejection and immutable intent
policy. No real Google writes were made. At deployment there are no paired desktop
accounts; an exact account allowlist must be configured after pairing before writes
can be submitted. Extension 0.3.1 supports the new policy with unchanged permissions
and protocol 2.
